# BankShield

Учебный **упаковщик Windows PE**: своё приложение шифруется, к нему дописывается загрузчик (stub). При старте пользователь запускает уже обёрнутый `.exe`.

Это репозиторий **исходников**. Собранные `bs_protect.exe` / `bs_stub.exe` в git не входят.

Проект рассчитан на **свой** Windows-бинарник (например, клиент банковского приложения), не на упаковку чужих файлов и не на произвольные документы. Сейчас в формате — только PE `.exe`.

## Состав

| Путь | Назначение |
| --- | --- |
| `src/bs_protect_v2.c` | Утилита упаковки |
| `src/bs_stub.c` | Загрузчик: читает себя, расшифровывает нагрузку, запускает оригинал |
| `src/bs_crypto.c` | AES-256-CBC, SHA-256, HMAC, цепочка хешей |
| `src/bs_pack_crypto.c` | PBKDF2, обёртка ключей, MAC формата v4 |
| `src/bs_antidebug.c` | Опциональные проверки отладчика |
| `src/bs_protect.c` | Старый путь: секции PE без отдельного stub |
| `include/` | Заголовки формата и API |
| `test/test_all.c` | Модульные проверки крипто и памяти |
| `Makefile` | Сборка MinGW-w64 |

Формат файла (с конца): хвост `BSHENDBB` → заголовок → шифротекст → в начале файл stub.

## Требования

- Windows
- MinGW-w64 (`gcc`, `make`)

## Сборка

```bat
make
```

Появятся (локально, не в git):

- `build/bs_stub.exe`
- `build/bs_protect.exe`
- `build/bs_test.exe`

Тесты:

```bat
make test
```

Демо: упаковать сам тестовый бинарник:

```bat
make protect-demo
```

Свой EXE:

```bat
make protect TARGET=myapp.exe OUTPUT=myapp_protected.exe
```

Или после `make`:

```bat
build\bs_protect.exe myapp.exe myapp_protected.exe
```

Опции: `--no-antidebug`, `--no-integrity`, `--no-hide`, `--stub путь\к\bs_stub.exe`.

Целевой машине отдельные DLL не нужны — только Windows. Stub собран как GUI; для консольных программ при запуске вызывается `AllocConsole`.

## Что это не делает

- Не шифрует PDF, картинки, скрипты и прочие не-PE файлы.
- Не заменяет HSM, подпись кода и нормальный секрет в банке.
- Ключи восстанавливаются в памяти при запуске; расшифрованный EXE на короткое время пишется во временный файл (`CreateProcess`). Флаг «только память» в заголовке зарезервирован и не реализован.
- Свой AES в учебном коде; для продакшена обычно CNG или проверенная библиотека.
- Anti-debug — не граница безопасности, мешает и легитимной отладке (`--no-antidebug`).

## Что не выкладывать на GitHub

- `build/`
- `*.exe`
- `.vscode/` (локальные пути компилятора)

`.gitignore` это уже отсекает. Не заливайте папку целиком вместе с `build`.
